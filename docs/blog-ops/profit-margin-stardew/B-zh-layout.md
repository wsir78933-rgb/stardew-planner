## 3. 读者前提与完成标志

### 读者可能已经有

- 一个准备新建的单人或多人农场，或一个想尝试限制条件的挑战目标。
- 四个可见选项（普通/100%、75%、50%、25%）或“利润率是什么意思”的疑问，但未必知道百分比只作用于明确列出的价格类别。
- 对前期卖货收入、种子成本、多人节奏或固定支出的实际关切；不需要先使用本站规划器。

### 读者读完后必须能

1. 说明游戏内 Profit Margin 是选定出售物品价格和种子价格的倍率设置，不是现实会计里的“净利润 ÷ 收入”。
2. 正确区分普通/100%、75%、50%、25% 的含义，并知道小数价格截断为整数且不低于 1g。
3. 从表格和例子中分辨会缩放的出售/种子/指定商品与明确不受影响的商店、建筑、工具升级和任务金币奖励。
4. 以单人、多人或挑战目标为条件选择数值，知道来源没有证明一个对所有人通用的“最佳值”。
5. 通过新游戏创建界面的扳手/高级游戏设置路径找到 Profit Margin，并在创建前检查自己的选择。

完成标志是读者能做出并解释一个新农场设置选择；不是承诺固定完成天数、固定年份、精确进度倍数、金币预测或平台无差别的 UI 位置。

## 4. 范围边界

### 必须覆盖

- 游戏内 Profit Margin 的直接定义及其与现实会计“利润率”的区别。
- 普通/100%、75%、50%、25% 四档；较低值同时影响来源明确列出的出售价格和种子价格，不能写成“所有价格都乘百分比”。
- 小数价格截断为整数且最低 1g 的规则。
- 受影响与不受影响类别的精确边界，使用来源支持的 Wheat 与 Willy 的 Crab Pots 两个示例。
- 单人、多人协作、挑战玩法的条件化选择；将“best/good”写成取决于目标的判断，不造一个普遍最佳值。
- 新农场的高层设置路径，以及“未逐平台实测”的平台/版本限制。
- 当读者遇到一个价格没有按直觉变化、或看不到设置入口时的安全判断分支：先对照来源明确列出的类别和新游戏路径；无法核验的平台/版本差异不要被改写成确定机制。

### 明确排除

- 泛赚钱路线、第一年现金行动清单、季度作物排名、作物/加工/ROI 计算、金币计算器。
- Mod、MoreProfitMargins 或其他扩展选项。
- 旧存档 XML 编辑、字段修改、备份流程、跨平台修复和“如何把现有存档改成某百分比”的教程。
- 精确的进度/完成时间、把 25% 说成必然慢两倍、统一金币损失、统一难度分数或受控实验结果。

## 7. H1/H2/H3 工作结构

以下是供 C-zh 落地的工作标题，不是最终 SEO Title。正文应写正常简体中文，不把字段名、事实 ID 或工作流口吻复制给读者。

### H2-1 — `星露谷物语的 Profit Margin（利润率）到底改变什么？`

- 先放 70–100 个合格汉字的 direct-answer 段落，回答选定出售价格/种子价格倍率、四档和非全局边界。
- 第一次提到设置时链接中文 Options；不写现实会计公式，只用一句区别说明。
- 可预告新农场高级设置入口，但完整路径留在 H2-5。

### H2-2 — `100%、75%、50%、25% 分别代表什么？`

- 用一个精确表格列出 `普通/Normal（100%）`、`75%`、`50%`、`25%`；表格的“倍率如何读”和“选择时意味着什么”分开。
- 表格旁说明：低值会压低来源明确列出的出售价格，也会压低列出的种子价格；不要写成所有购买行为或所有支出都变化。
- 紧邻表格说明小数价格截断为整数且不低于 1g，链接英文 Options。
- H3 — `75% 利润率是什么意思？`：直接回答对应 PAA，使用倍率语言；不得写成现实利润率。
- 不在此处给出四次重复长解释；具体适用场景集中到 H2-4。

### H2-3 — `哪些价格会随利润率变化，哪些不会？`

- 先给两列矩阵：`受 Profit Margin 影响` / `不受 Profit Margin 影响`。矩阵只放 A-zh 事实台账中明确的类别，表格后再用简短正文解释如何读。
- H3 — `会变化的范围：出售物品、种子和指定商品`
  - 按 Multiplayer 来源列出的范围写：作物、采集物、矿物、烹饪食物等出售物品示例；Pierre 种子；Joja 的 Grass Starter、Sugar、Wheat Flour、Rice 等指定商品。
  - 使用“来源列举/指定类别”措辞，不把 `most items` 外推为所有商店、所有原料或所有购买价。
- H3 — `不会变化的范围：部分商店、建筑、升级和任务奖励`
  - 明确列出铁匠、鱼店、旅行货车商品、建筑、工具升级和任务金币奖励不受影响。
  - 用 Willy 的 Crab Pots 仍为 1,500g 做一个例子；不把单个例子外推成所有商店规则。
- H3 — `看到一个价格没有按预期变化时先检查什么？`
  - 让读者先把该物品/费用对照两列矩阵和来源的指定清单；无法归类时标记为待核验，不下“游戏一定出错”或“所有价格都不变”的结论。
- 矩阵和短例子之后放 Figure 1。图不取代表格，也不新增未引用类别。

### H2-4 — `单人、多人和挑战存档怎么选利润率？`

- 开头先给条件化结论：公开来源没有证明任一数值对所有玩家普遍最佳；选择输入是玩家人数、期望节奏和对较紧出售收入经济的接受度。
- 放一个决策矩阵：场景/目标 → 可先考虑的档位 → 必须说明的取舍。档位建议是编辑判断，不能伪装成 Wiki 规则或实测难度分数。
- H3 — `单人新农场：以普通（100%）作为标准起点`
  - 把普通写成基准经济，不写“唯一正确”或“对所有人最好”。
  - 如提到早期预算压力，说明这是低出售收入与种子价格一起变化的推理，不扩展成第一年赚钱路线。
- H3 — `多人协作：根据人数和期望约束考虑降低档位`
  - 使用 Multiplayer 来源关于多人生产力/降低利润率作为经济再平衡的机制说明。
  - 75% 可作为“中等约束”的编辑建议，50% 可作为更紧约束候选；两者都不能写成通用平衡答案或精确进度保证。
- H3 — `挑战玩法：25% 利润率是有意收紧经济的选择`
  - 可引用社区/挑战结果仅说明此类需求存在；机制和价格必须回到 Wiki。不得把个人存档收益、视频进度或 25% 变成普遍规律。
- H3 — `75% 利润率适合吗？`
  - 用一段条件式回答：当玩家想保留标准玩法框架、同时接受较紧约束时可考虑；是否“适合”取决于人数和目标，不重复整张表。
- H3 — `25% 利润率适合什么情况？`
  - 用一段条件式回答：适合主动追求更紧经济/挑战的人；不声称固定慢几倍、少赚多少或更容易/更难完成某目标。
- 只在本节一次链接中文站内的第一年赚钱文章，作为预算背景补充，不复制其行动路线。
